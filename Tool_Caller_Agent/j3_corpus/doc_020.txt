### SOC Runbook Excerpt: Handling a DDoS Attack Against Public-Facing Web Infrastructure

#### Objective:
The objective is to mitigate the impact of a Distributed Denial of Service (DDoS) attack on public-facing web infrastructure while ensuring minimal disruption to legitimate user traffic.

---

**Step 1: Initial Detection and Traffic Analysis**

- **Date/Time:** April 20, 2023
- **Affected Hostnames/IPs:** `www.examplecorp.com` (IP: 192.168.1.1), `api.examplecorp.net` (IP: 192.168.2.1)
- **Attack Indicators:**
  - Sudden increase in traffic volume to over 50Gbps.
  - A significant number of SYN packets with forged source addresses.
  - Anomalously high request rates on the API endpoint.

**Traffic Analysis Steps:**

1. **Monitor Network Traffic:** Utilize tools like `Wireshark` or `NetFlow` to analyze network traffic in real-time.
2. **Anomaly Detection:** Implement threshold-based alerts for unusual traffic patterns using security information and event management (SIEM) systems such as Splunk or Elastic Stack.
3. **Source IP Analysis:** Identify and block suspicious IPs using a custom script that cross-references with a known bad IP database like `AlienVault OTX`.

---

**Step 2: Upstream Provider Coordination**

- **Date/Time:** April 20, 2023
- **Upstream ISP:** Cloudflare

1. **Contact ISP:** Engage with the upstream provider's DDoS mitigation team via their support portal or phone.
   - Provide details of the attack (e.g., start time, IP addresses).
   - Request immediate prioritization and application of necessary defense measures.

2. **ISP-Provided Tools:** Leverage the provider’s tools such as `Anycast DNS` for load distribution or `DDoS Shield` to divert malicious traffic.
3. **Feedback Loop:** Monitor the effectiveness of the mitigation actions through real-time updates from the ISP.

---

**Step 3: Web Application Firewall (WAF) Rule Deployment**

- **Date/Time:** April 20, 2023
- **WAF System:** ModSecurity

1. **Configure WAF Rules:**
   - Deploy rate-limiting rules to throttle excessive requests from suspicious sources.
     ```apache
     SecRule IP_ADDRESS "@eq 65534" "id:90001,phase:2,t:none,nolog,pass,msg:'Rate Limit Exceeded',setvar:tx.rate_limit=on"
     ```
   - Implement a CAPTCHA challenge for users from high-risk geolocations.
     ```apache
     SecRule GEO:COUNTRY_CODE "@streq 'RU'" "id:90002,phase:1,t:none,nolog,pass,msg:'Geographical Risk',setvar:tx.captcha_required=on"
     ```

2. **Test Rules:** Thoroughly test the new rules in a staging environment to ensure they do not impact legitimate user traffic.
3. **Monitor Performance:** Continuously monitor WAF logs for any false positives and adjust rules as necessary.

---

**Conclusion:**
By following these steps, the SOC team can effectively mitigate the DDoS attack, ensuring that `www.examplecorp.com` and `api.examplecorp.net` remain accessible to legitimate users while minimizing potential damage. Regular updates and reviews of the mitigation strategies are essential to stay ahead of evolving DDoS threats.

---
