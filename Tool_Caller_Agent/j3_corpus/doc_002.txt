### SOC Runbook Excerpt: Containment Procedure for Compromised Windows Endpoint

#### **1. Incident Overview**
On March 15, 2023, at 14:30 UTC, the Endpoint Detection and Response (EDR) system detected a suspicious activity on Hostname-WIN-123 on IP Address 192.168.1.10. The alert indicated that the machine had been compromised with unauthorized software installation and potential lateral movement to other endpoints.

#### **2. Objective**
The objective of this procedure is to contain the incident, prevent further spread, and gather evidence for forensic analysis.

#### **3. Immediate Actions**

**Step 1: Isolate the Compromised Host**
- **Action:** At 14:35 UTC, isolate Hostname-WIN-123 from the network by disabling its network connection or placing it in a designated DMZ.
- **Justification:** This action prevents further spread of malware and minimizes potential damage.

**Step 2: Suspend All Active Processes**
- **Action:** At 14:40 UTC, suspend all active processes on Hostname-WIN-123 via the Task Manager or using a PowerShell command.
- **Justification:** This action halts any ongoing malicious activities and preserves evidence in its current state.

**Step 3: Secure System Logs**
- **Action:** At 14:45 UTC, initiate a log collection process to capture all system logs, including Security Event Log, Application Log, and System Log. Use the EDR tool to export these logs.
- **Justification:** Securely collected logs are critical for forensic analysis.

**Step 4: Disable Unnecessary Services**
- **Action:** At 14:50 UTC, disable any unnecessary services that could potentially be used by malware (e.g., Remote Desktop, SNMP).
- **Justification:** This reduces the attack surface and prevents further exploitation of open services.

#### **4. Escalation Criteria**

**Criteria A:** If Hostname-WIN-123 is unable to communicate with the EDR system or other critical systems.
- **Action:** Elevate incident to Tier 2 Support at 15:00 UTC.

**Criteria B:** If there are indications of data exfiltration or lateral movement beyond Hostname-WIN-123.
- **Action:** Immediately notify the Security Incident Response Team (SIRT) at 14:47 UTC and proceed to Step 5.

#### **5. Evidence Preservation**

**Step 5: Collect Additional Forensic Data**
- **Action:** At 15:05 UTC, use a trusted forensic tool to perform a memory dump of Hostname-WIN-123.
- **Justification:** Memory dumps can provide critical insights into the state of the system at the time of compromise.

**Step 6: Prepare for Incident Review**
- **Action:** At 15:10 UTC, prepare all collected data (logs, memory dump) for review and analysis by the SIRT.
- **Justification:** Proper documentation ensures a thorough understanding of the incident for future prevention strategies.

#### **6. Post-Incident Actions**

**Step 7: Conduct a Detailed Analysis**
- **Action:** At 15:30 UTC, initiate a detailed analysis of all collected data to identify the nature and extent of the compromise.
- **Justification:** This step is crucial for understanding the attack vector and improving security measures.

**Step 8: Patch and Update Systems**
- **Action:** Upon conclusion of the analysis, apply any necessary patches or updates to Hostname-WIN-123 and all affected systems.
- **Justification:** Ensures that vulnerabilities are closed and helps prevent future incidents.
