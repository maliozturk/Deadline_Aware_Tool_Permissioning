### SOC Runbook Excerpt: Responding to Ransomware Infection on a File Server

#### **Incident Summary**
On March 15, 2023, at 14:30 UTC, the Security Information and Event Management (SIEM) system alerted the Security Operations Center (SOC) team of suspicious activities on the file server named `FILESVR01` with an IP address of 192.168.10.50. The initial indicators suggest a ransomware infection has been detected.

#### **Objective**
The primary objectives are to contain the threat, verify backups, and initiate recovery procedures without compromising data integrity or availability.

---

### **Step 1: Isolation**

**Immediate Actions:**
- At 14:35 UTC, isolate `FILESVR01` from the network to prevent further spread.
- Disconnect all directly connected storage devices (e.g., USB drives) from `FILESVR01`.

**Tools Used:**
- Network isolation using firewall rules.
- Physical disconnection of storage media.

**Documentation:**
- Log the time and actions taken in the incident response log.
- Update the network topology diagram to reflect the current state.

---

### **Step 2: Backup Verification**

**Objective:** Ensure that an uninfected backup exists and is usable for recovery.

**Actions:**
- At 14:45 UTC, verify the integrity of the latest backup stored in `BACKUP01` with IP address 192.168.10.52.
- Use the automated backup verification tool to confirm that all necessary files are present and unmodified.

**Tools Used:**
- Automated backup verification software (e.g., Veritas Backup Exec).

**Documentation:**
- Record the verification results in the incident response log.
- If any issues arise, report them immediately for further analysis.

---

### **Step 3: Negotiation Policy Reference**

**Objective:** Understand the organization's policy on ransomware negotiations to ensure compliance and ethical handling of the situation.

**Actions:**
- At 15:00 UTC, consult the `RansomwareNegotiationPolicy.docx` document located in the shared drive `SHARED drive \ Security\ Policies`.
- Review clauses related to engagement with ransomware actors, data recovery methods, and legal considerations.

**Documentation:**
- Note any relevant policies or guidance in the incident response log.
- If the policy allows for negotiation, proceed with caution and ensure all steps are documented.

---

### **Step 4: Recovery Procedure Outline**

**Objective:** Restore the system to a clean state while minimizing downtime and data loss.

**Actions:**
- At 15:30 UTC, initiate the recovery process using the verified backup from `BACKUP01`.
- Migrate all critical files and configurations back to `FILESVR01` over a secure connection.
- Perform a post-recovery check to ensure system integrity and functionality.

**Tools Used:**
- Automated migration tool (e.g., Migration Assistant).
- Post-check script to validate file integrity.

**Documentation:**
- Document the recovery steps in detail, including any manual configuration changes made during the process.
- Update the incident response log with a summary of actions taken and outcomes observed.

---

### **Next Steps**

- Conduct a thorough investigation into how the ransomware infection occurred to prevent future incidents.
- Review and update security policies and procedures based on findings from this incident.
- Notify relevant stakeholders (e.g., IT management, legal department) about the resolution status and any required actions.
