### SOC Runbook Excerpt: Handling a DDoS Attack Against Public-Facing Web Infrastructure

#### Scenario Overview:
On January 15th, 2023, the security operations center (SOC) received an alert from Cloudflare indicating unusually high traffic on our public-facing web infrastructure hosted at `www.examplecorp.com`. The network traffic was significantly higher than normal, with over 90% of the incoming traffic originating from a few IP addresses and multiple geolocations. 

#### Traffic Analysis:
1. **Initial Assessment**:
   - Review the alert generated by Cloudflare’s Security Dashboard.
   - Analyze real-time traffic patterns using tools like `NetFlow` or `IPFIX` data from our network monitoring solution, `Plixer StealthWatch`.
   - Identify the top 10 IP addresses responsible for the majority of traffic.

2. **Traffic Pattern Analysis**:
   - Use `Wireshark` to inspect packets and identify common signatures such as SYN flood attacks.
   - Check if there are any unusual spikes in HTTP GET or POST requests, which could indicate an application-level DDoS attack.
   - Evaluate the packet size distribution; a large number of small packets might suggest a volumetric attack.

3. **Geo-Location Analysis**:
   - Utilize `MaxMind` for geolocation data to map out the geographical locations of the malicious IPs.
   - Cross-reference with known bad actor IP ranges from the `OTX` (Open Threat Exchange) by CrowdStrike, which can provide a list of potential malicious sources.

#### Upstream Provider Coordination:
1. **Initial Contact**:
   - Notify our primary Internet Service Provider (ISP), `NetConnect Inc.,` and request immediate support.
   - Provide them with the IP addresses identified as part of the attack for blacklisting purposes.

2. **Escalation Steps**:
   - If initial coordination does not yield results, escalate to a senior technical liaison at NetConnect Inc.
   - Consider involving other upstream providers like `NetSpeed Solutions` if additional bandwidth is required or if specific regions are being targeted.

3. **ISP Actions**:
   - Request that the ISP implement rate limiting on our network interfaces to mitigate the impact of the DDoS attack.
   - Ask for their assistance in rerouting traffic through a scrubbing center if available, which can help clean and forward legitimate traffic.

#### WAF Rule Deployment:
1. **Identify Vulnerabilities**:
   - Use `OWASP ZAP` or similar tools to scan the web application for vulnerabilities that could be exploited.
   - Prioritize rules based on the nature of the detected attacks (e.g., SQL injection, cross-site scripting).

2. **Rule Configuration**:
   - Deploy a comprehensive set of Web Application Firewall (WAF) rules using Cloudflare’s `WAF` service.
   - Configure rate limiting to prevent abuse and ensure that legitimate traffic can still pass through.
     - Example: Limit POST requests to 100 per minute from any single IP address.

3. **Testing**:
   - Perform a test by sending controlled traffic to simulate the attack scenario to verify the effectiveness of the deployed WAF rules.
   - Monitor `Cloudflare’s Real-Time Analytics` dashboard for signs of improvement in performance and reduced traffic volume.

4. **Monitoring and Logging**:
   - Enable detailed logging on both our web servers and Cloudflare to capture all relevant information during the attack.
   - Regularly review logs to ensure that no new vulnerabilities are exposed or exploited by attackers.

By following these steps, we can effectively manage a DDoS attack against our public-facing infrastructure while ensuring minimal disruption to legitimate users.
